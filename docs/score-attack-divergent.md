# 結果が分かれた棋譜への挑戦

スコアアタック開始メニューの通常開始ボタンの下に専用の入口を表示する。
AI・棋譜別ランキングは通常のスコアアタックと共通。
専用挑戦のデイリー・ウィークリー加算は、実際の点差の符号から＋10・0・−10点に換算する。

## 自動抽出

- 終局済みの `ranked=1` の記録を使用し、同じ参加者・課題は1件にする。
- ゲストの保存期限が過ぎた記録、再挑戦、練習、未完了の挑戦は含めない。
- 初回挑戦者が3人以上、最高点と最低点の差が50点以上、四分位範囲が20点以上。
- 四分位数はソートした点差の `(件数 - 1) * 割合` の位置を線形補間する。
- 上記に合う課題と、既存の現在利用可能な棋譜候補を照合してからランダムに選ぶ。
  要確認・除外・不正・範囲外・現在のアーカイブにない棋譜を復活させない。
- 条件を満たす棋譜がない場合は案内を表示し、通常開始へ自動で切り替えない。

開始時に毎回集計するため、固定の棋譜リストや追加の定期処理は不要。
3人の結果は偏りやすく、「戦略的に面白い」と保証する指標ではない。

## 終了後の比較

専用入口から開始した挑戦は `trace_attempts.selection_mode=divergent` として保存。
過去の履歴から開いても比較を表示できる。既存記録は `random` として保持する。

結果APIは本人の終局を確認した後にのみ、ほかの参加者の初回結果を匿名で返す。
本人の全挑戦を除外し、点差ごとの人数でまとめる。表示時点の有効な記録を使用するため、
その後の挑戦やゲスト記録の期限切れによって分布は変化する。
ほかの参加者の記録がすべてなくなった場合は比較欄を表示しない。

## ランキングへの加算

- `improvement` は実際の点差のまま保存し、棋譜別ランキング・履歴・比較・自動抽出に使う。
- `selection_mode=divergent` はプラスなら＋10点、0なら0点、マイナスなら−10点。
- 通常挑戦は従来どおり実際の点差で加算する。
- 同じ参加者・棋譜の最初の完了結果で、通常／専用のどちらを総合集計に使うか決める。
  後から別の方法で遊んだ記録は履歴・棋譜別ランキングに残すが、総合集計には重ねて加算しない。
  同じ方法での再挑戦は、従来の毎回集計を維持する。
- 結果画面に `ranking_points` と `ranking_counted` に基づく加算点・対象外の案内を表示する。
- デイリー・ウィークリー（前週を含む）・報酬候補の集計は同じSQLを使う。
  週のマイナス日を0とする既存ルールは、換算した日合計に適用する。
- 保存済みの専用挑戦も集計時に換算する。確定済みの会員報酬の付与・取り消しは行わない。

通常の初回・再挑戦判定は変更しない。この入口で同じ棋譜を引いても初回には戻らない。

## 全員同点の棋譜の自動除外

通常・専用の出題時に、初回挑戦が3人以上で、その全員の `improvement` が同じ課題を外す。
「0、0、0」は除外するが「0、0、0、50」は除外しない。
換算後の＋10・0・−10点では判定しない。再挑戦・練習・未完了・期限切れは人数に含めない。

既存のアーカイブ候補キャッシュを取り出した後に毎回判定し、更新を即座に反映する。
棋譜・挑戦履歴の削除や監査の手動状態の書き換えは行わない。
有効な記録が条件を満たさなくなれば自動除外も解除される。

## 確認

`tests/test_divergent_score_attack.py` で人数・点差・ばらつきの境界、再挑戦・期限切れ等の除外、
匿名比較、通常開始、所有者制御、開始前の結果非公開、加算点の換算、方法切り替え時の重複防止、
報酬・前週ランキングとの一致、全員同点の自動除外を確認する。
