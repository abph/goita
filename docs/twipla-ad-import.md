# ツイプラから地域別広告を作成する

管理者ページ → **地域別広告** → **広告の編集** の「ツイプラから取り込む」に
`https://twipla.jp/events/数字` のイベントURLを入力し、**情報を取得**を押します。

- イベント名・開催日時・会場を読み取り、見出し・短い本文・リンク先・掲載日時を入力します。
- 掲載開始は取得時点です。開催開始日時とは別です。
- 取得元のイベント名・日時・会場を表示します。見出しは40文字、本文は200文字以内です。
- 終了時刻を取得できない場合、掲載終了は空欄になります。元のページを確認して入力してください。
- 対象地方・表示場所・背景色は勝手に変更しません。特に対象地方は会場を見て確認してください。
- 取得しただけでは保存・掲載しません。内容を編集・確認し、掲載する場合は
  **掲載を有効にする**を選び、**広告を保存**します。
- 保存後は既存の掲載期間の仕組みにより、終了日時以降は配信対象から外れます。
- 終了済みイベントには注意を表示します。次回のイベントには次回のURLを登録してください。

取得は管理者がボタンを押したときだけ行います。定期取得・自動更新・参加者情報の取り込みは行いません。
取得できなかった場合は、既存の編集内容と保存済み広告を維持し、従来どおり手入力できます。

## 実装と検証

`POST /admin/api/regional-ads/import-twipla` は管理者認証を必須とし、下書きだけを返します。
公開ツイプライベントのHTTPSページに取得先を限定し、リダイレクト・応答サイズ・待ち時間を制限します。
外部HTMLをそのまま表示せず、必要な文字情報だけを抽出します。追加の依存ライブラリは不要です。

ツイプラのカレンダー用リンクは開始・終了が同時刻になることがあるため、本文の対応する
日時行も参照します。取得形式が変わった場合は、手動確認に戻れる設計です。

検証:

```text
python -m pytest tests/test_twipla_import.py tests/test_regional_ads.py -q
node tests/twipla_import_ui_behavior.cjs
node tests/regional_ads_ui_behavior.cjs
```
