# 会員のルーム管理

運営の管理者ページ → 会員管理で「研究用プラン」をオンにし、「管理する部屋」を選んで保存します。新規発行時にも指定できます。既存会員の割り当ては自動で行いません。

- 1会員につき1部屋、1部屋につき1会員です。公開部屋・デバッグルームは割り当てられません。
- 研究用プランの会員には、マイページに「ルーム管理」タブが表示されます。有効な有料権限と初回パスワード変更が必要です。
- 入室せずにルーム名、入室用の合言葉、AI、ログ・合法手の表示、着席者の管理を操作できます。管理用パスワードの再入力は不要です。
- 「この部屋に入る」から通常の入室へ進めます。入室用の合言葉がある場合は従来どおり入力します。
- 研究用プランをオフにすると部屋の割り当ても解除されます。有料権限の期限切れ・無効化だけでは割り当てを保持し、マイページからの管理を停止します。再割り当ては先に元の会員の割り当てを解除してください。
- 既存の管理用パスワード方式は移行用に残ります。会員の権限変更では従来の管理用パスワードは変更されません。以前の管理者から部屋を引き継ぐ場合は、運営側で管理用パスワードも変更してください。

会員データベースへ `research_enabled` と `managed_room_id` を自動追加します。既存会員は研究用プランなし・割り当てなしで保持されます。部屋の重複割り当てはDBの一意制約でも防止します。会員DBと部屋設定の既存の永続保存先を使用するため、デプロイ時の追加環境変数は不要です。

会員の専用APIは `/api/member/room`、`/settings`、`/vacate` です。各リクエストで同一サイト、現在のログイン、有料権限、研究用プラン、割り当てを検証します。更新リクエストの部屋IDは現在の割り当てと一致する必要があり、別の部屋に権限を広げる指定はできません。退席操作は既存の着席者確認トークンを使用します。サイト全体の管理権限は付与しません。

検証: `pytest tests/test_member_room_management.py`。画面の検証は Playwright と Microsoft Edge のある環境で `node tests/member_room_ui_behavior.cjs` を実行します。
