# VRChat A席＋サイトC席の協力プレイ（0.3.0）

## 導入

この版はUnityだけでは動作しません。サーバー・サイトの更新と、ワールドの再アップロードが必要です。公開サーバーへのデプロイやGitのコミット・pushは実装作業では実行していません。

サーバー側の対象ファイル:

- `backend/app.py`
- `backend/vrc_solo_web.py`（新規）
- `frontend/index.html`
- `frontend/vrcSoloCoop.js`（新規）

既存のRenderの起動コマンドはそのまま利用できます。ゲームはメモリー上にあるため、従来どおり1プロセス・1ワーカー・1サービスインスタンスで運用してください。

```sh
uvicorn backend.app:app --host 0.0.0.0 --port $PORT --workers 1
```

GitHub連携の自動デプロイ環境なら、変更を確認・コミットしてpushしたあとにRenderのデプロイ完了を確認します。自動デプロイが無効なら `Manual Deploy > Deploy latest commit` を実行します。現在の作業ツリーには別作業のステージ済み変更もあるため、無条件の `git add .` や `git commit -a` は使用せず、今回の差分と既存変更を確認してからコミットしてください。

Unityでは卓のルートを選び、次のメニューを実行します。

`Tools > AI Solo Goita Table > Enable Website Partner on Selected Table`

34 URL × 128組の接続設定に更新し、側面3段目にC → AIボタンを追加します。従来の盤面と表示位置は変更しません。シーンを保存し、対象プラットフォームごとにワールドを更新してください。

## 遊び方

1. VRChat側でA席へ参加し、STARTを押す。
2. サイトの人が `https://solo.vrcgoita.com/?room=vrc-solo-table1` を開く。
3. 「C席で参加・再接続」を押す。ほかのサイト利用者は観戦になる。
4. VRChat側でC席参加を確認し、もう一度STARTを押す。
5. A・Cの人間チーム対B・DのAIチームで対局する。
6. 終局後はVRChat側のNEXT ROUNDで続行。C席・名前・点数を維持する。NEW MATCHでは点数をリセットし、C席の参加者は維持する。
7. 終了はVRChat側の「利用終了」を10秒以内に二度押す。

Room IDを変更している場合、リンク末尾の`table1`を設定したIDに合わせてください。URLは参加権を限定する認証リンクではなく、C席は先着1人です。

## 同期と秘密情報

- サーバーが対局の正本。サイトの着手後もサーバーがAIの手番を進め、ブラウザ観戦者のCPUリクエストには依存しない。
- VRChat所有者が約6秒間隔で状態を取得し、同じインスタンス内へ同期する。通信時間やUdonの通信待ちが加わるため即時反映ではない。
- 同じ盤面の取得ではA席の駒選択を解除せず、出した手駒の隙間も維持する。
- 対局中、サイトにはC本人の手駒だけを送り、VRChatにはCの残り枚数だけを送る。伏せ駒の非公開を維持し、終局後に全員の手駒・伏せ駒を公開する。
- サイトからはA・B・Dへの着席、AI設定変更、開始、リセット、手駒の強制公開を拒否する。
- ブラウザの`client_id`は既存サイトと同じ端末識別方式。アカウント認証ではない。VRChatのURL内識別子も認証用の秘密鍵ではない。

## 切断・交代

- サイトは6秒間隔でC席の生存確認を送る。30秒以上確認できなければ再接続待ち表示になる。
- 最後の確認から120秒は席を保持。同じブラウザの再読み込みで復帰可能。別ブラウザや別端末への引き継ぎは初版では未対応。
- 120秒経過後も自動でAIにはせず、A席がC → AIを10秒以内に二度押して交代する。C本人がサイトで退出した場合はすぐに交代可能。
- 新規参加前の待機中もC → AIで1人用として開始可能。
- AIへ交代するとその利用が終わるまでC席はAIのまま。再び人間を参加させるにはVRChatで利用終了し、STARTで新しく開始する。
- サイトからの生存確認はVRChat側の使用権を延長しない。VRChatの通信が途絶えて180秒経過するとサイト側も終了表示になり、別インスタンスが利用可能になる。
- 利用終了・サーバー再起動・新しい使用者への交代後に、古いC席の操作は継続できない。

## 検証

```text
python -m pytest tests/test_vrc_solo_bridge.py tests/test_vrc_solo_coop.py -q
node tests/vrc_solo_coop_ui_behavior.cjs
node tests/immediate_actions_ui_behavior.cjs
node tests/hand_rehide_ui_behavior.cjs
```

テストは専用のSQLiteファイル・仮想HTTPクライアントを使用し、公開対局を変更しません。ブラウザテストにはPlaywrightとEdgeが必要です。Unityでは確認用プロジェクトでUdonコンパイル、34本URL生成、更新メニュー再実行、未変更ポーリング時の駒選択保持を確認します。実際のVRChatと公開サイトをまたぐ実機対局は、デプロイとワールド更新後に確認してください。
